## Migration-time versus runtime effects

M1 performs schema creation, grants/policies/triggers, and inserts one default settings row. M2 renames/adds enum labels, adds columns/index, and runs a top-level UPDATE backfilling closed_at from resolved_at for closed enquiries (M2:26). No file performs top-level DROP TABLE, DROP SCHEMA, TRUNCATE, or customer DELETE. Runtime functions do prune expired rate buckets (M1:219) and delete enquiries (M1:310); those functions were not invoked in this inspection.

IF NOT EXISTS and duplicate_object handlers do not validate incompatible existing table/index/enum definitions. CREATE OR REPLACE overwrites function definitions; DROP/CREATE replaces named triggers/policies. Re-execution is not guaranteed harmless and the migration files must not be used to repair an unknown remote schema speculatively.
